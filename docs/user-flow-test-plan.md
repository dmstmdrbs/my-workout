# Trainlog 사용자 플로우 테스트 계획

현재 검증 범위는 `localStorage` 기반 mock adapter를 사용하는 웹앱이다. Supabase와 Google 로그인은 adapter 연결 이후 별도 시나리오로 검증한다. 운영 DB에서는 새 프로필에 기본 종목이 사용자 소유로 생성되는지, 기존 루틴·기록·1RM이 사용자 소유 복제본을 계속 참조하는지 추가로 확인한다.

## 공통 합격 기준

- 화면 전환 중 입력 데이터가 의도치 않게 사라지지 않는다.
- 목표 RIR과 실제 RIR은 별도 값으로 유지된다.
- 저장 성공 후 새로고침해도 루틴과 완료 운동이 남아 있다.
- 실패하거나 비어 있는 상태에서 사용자가 다음 행동을 알 수 있다.
- 데스크톱과 모바일에서 핵심 행동이 가려지거나 조작 불가능하지 않다.

## 시나리오

### UF-29 프로필·친구 초대와 관계 관리

1. `/friends`에서 친구, 받은 요청, 보낸 요청과 초대 링크 영역을 확인한다.
2. 받은 요청을 수락하고 보낸 요청을 취소한다.
3. 내 초대 링크를 생성·공유한 뒤 다른 사용자로 `/friends/invite/:token`을 연다.
4. 초대 화면에서 요청을 보내고 초대한 사용자로 돌아와 수락한다.
5. 친구 상세에서 친구를 삭제하거나 차단하고, 차단 목록에서 해제한다.
6. `/profile`에서 표시 이름을 바꾸고 친구 화면으로 돌아온다.
7. 데스크톱과 모바일 너비에서 친구 메뉴, 요청 수 배지와 더보기 메뉴를 확인한다.

기대 결과:

- 이메일은 친구 화면이나 응답에 노출되지 않고 표시 이름과 아바타만 보인다.
- 유효한 초대, 내 링크, 만료·폐기 링크, 보낸 요청, 받은 요청, 이미 친구인 상태를 구분해 다음 행동을 안내한다.
- 수락·거절·취소·삭제·차단 결과가 목록과 요청 수 배지에 즉시 반영된다. **(자동 테스트 검증 -- mock adapter)**
- 차단하면 기존 관계와 대기 요청이 함께 사라지며, 해제해도 친구 관계가 자동 복원되지 않는다. **(자동 테스트 검증 -- mock adapter)**
- 표시 이름 변경은 내 프로필과 친구 기능용 공개 프로필에 함께 반영된다. **(자동 테스트 검증 -- mock adapter)**
- 모바일 하단 주 탭은 기존 4개와 더보기를 유지하고, 친구·프로필은 더보기에서 연다.
- 실제 사용자 두 명의 교차 브라우저 동작과 RLS는 `20260829165016_add_friend_system.sql` 적용 후 별도로 확인한다.

### UF-25 고정 7일 프로그램 회차

1. 프로그램 카탈로그에서 4개 선택지를 확인한다. 상체 중심 저피로 프로그램은 상체 3일과 하체·Zone 2 1일로 표시되어야 한다.
2. 다른 프로그램을 선택하고 주차별 Day와 실제 종목·세트 처방을 펼쳐 본다.
3. 시작일을 지정하고 `프로그램 시작하기 · 내 루틴에 가져오기`를 누른다.
4. 일반 운동 시작 화면의 내 루틴에서 `PROGRAM DAY 1` 카드를 열고 한 세트 이상 완료해 저장한다.
5. 운동 기록 상세와 프로그램 Day 완료 상태를 확인한다.
6. 프로그램을 중도 하차한 뒤 다시 시작한다.
7. 더 높은 템플릿 버전이 있으면 `최신 처방 적용`을 누르고 보존 범위 안내를 확인한다.

기대 결과:

- 시작일은 Day 1이고 매 회차는 휴식일을 포함한 56개의 달력 Day를 가진다.
- 선택한 프로그램의 이름과 처방이 회차 스냅샷에 저장되고, 활성 Day가 대시보드·루틴 관리·운동 시작의 내 루틴에 표시된다.
- 탑세트와 백오프 처방은 메모뿐 아니라 세트 유형으로 저장되며 운동 화면에서 서로 다른 배지 색으로 즉시 구분된다. **(자동 테스트 검증)**
- Day 3과 Day 7은 운동 누락 여부와 관계없이 `휴식일`이다.
- 프로그램 운동 저장과 해당 Day 완료 연결은 함께 반영된다.
- 최신 처방 적용 시 오늘보다 이전인 Day, 완료한 휴식일, 상태와 관계없이 운동 기록이 연결된 Day는 바뀌지 않고 오늘 이후의 미완료·기록 미연결 Day만 새 처방으로 교체된다.
- 중도 하차해도 기존 운동 기록과 종료 회차가 유지된다.
- 다시 시작하면 기존 회차를 이어 쓰지 않고 새로운 회차의 Day 1부터 시작한다.
- 지난 운동을 놓쳐도 이후 Day의 날짜는 밀리지 않는다.
- 네 프로그램 모두 4·8주차에 종목별 본세트가 약 35-50% 줄고 목표 RIR이 4로 바뀐다.
- 2분할·러닝 프로그램은 Day 4 상체 후 짧은 이지런과 Day 6 장거리 러닝으로 주 2회 달린다. Day 4 직접 팔 운동은 어깨 1세트로 바꾸고, Day 1과 Day 5를 합쳐 이두·삼두 각각 일반 주차 10세트, 3·6주차 12세트의 직접 볼륨을 제공한다.
- 전신 3일 프로그램은 일반 주차에 가슴 9세트, 대퇴사두 8세트, 햄스트링 7세트, 종아리 4세트의 직접 볼륨을 제공한다.

### UF-01 대시보드 진입과 메뉴 이동

1. 저장소를 초기화하고 앱을 연다.
2. 주간 지표, 최근 운동, 내 루틴을 확인한다.
3. 대시보드, 운동 시작, 루틴, 기록 메뉴를 차례로 연다.
4. `전체 보기`, `관리`, 최근 기록 행, 루틴 행, 상단 더보기 메뉴를 연다.

기대 결과:

- 시드 데이터가 오류 없이 렌더링된다.
- 선택된 메뉴가 명확히 표시된다.
- `전체 보기`와 최근 기록 행은 기록 화면으로 이동하며, 행에서 선택한 기록이 열린다.
- `관리`와 루틴 행은 루틴 화면으로 이동하며, 행에서 선택한 루틴이 열린다.
- 상단 더보기 메뉴에서 통계와 설정 화면으로 이동할 수 있다.
- 기능이 없는 버튼은 동작하는 것처럼 노출되지 않는다.

### UF-02 루틴을 선택해 운동 시작

1. 운동 시작 화면을 연다.
2. `Pull Day`를 선택하고 시작한다.
3. 첫 종목의 목표 중량, 반복 수, 목표 RIR을 확인한다.

기대 결과:

- 루틴 처방이 운동 초안으로 복제된다.
- 실제 RIR은 선택 전까지 미기록 상태다.
- 목표 RIR은 실제 RIR 입력으로 변경되지 않는다.

### UF-03 세트 기록과 휴식 타이머

1. 각 세트에서 같은 종목의 가장 최근 완료 세션 중 같은 순서 세트의 중량·횟수·유형을 확인한다.
2. 이전 세션보다 현재 세트가 많을 때 대응 기록 없음 안내를 확인한다.
3. 첫 세트의 중량과 반복 수를 변경한다.
4. 실제 RIR을 선택한다.
5. 세트를 완료하고 다시 완료를 취소한다.
6. 본세트를 추가한다.

기대 결과:

- 입력값과 실제 RIR이 초안에 반영된다.
- 이전 세션 비교값은 현재 세트의 같은 `setOrder`끼리 대응하며 세트 유형을 보존한다. 대응 세트가 없으면 빈 상태를 명확히 표시한다. **(자동 테스트 검증 -- mock adapter)**
- 현재 세션의 다른 세트를 입력하거나 완료해도 이전 세션 비교값은 덮어써지지 않는다. **(자동 테스트 검증 -- mock adapter)**
- 세트 완료 시 휴식 타이머가 시작된다.
- 완료 취소가 가능하다.
- 추가 세트는 처방값을 복제하지만 실제 RIR은 미기록 상태다.

### UF-04 진행 중 운동 보존과 이탈 보호

1. 세트 값을 입력한 상태에서 다른 메뉴로 이동한다.
2. 이탈을 취소한 뒤 입력값이 남아 있는지 확인한다.
3. 이탈을 승인하고 다시 운동 화면을 연다.
4. 별도 실행에서는 입력 후 새로고침한다.

기대 결과:

- 우발적인 메뉴 이동에는 확인 절차가 제공된다.
- 이탈 취소 시 초안이 유지된다.
- 새로고침 후 진행 중 초안을 복원할 수 있다.
- 명시적 취소 시 임시 초안이 제거된다.

### UF-05 운동 완료와 기록 반영

1. 완료 세트가 없는 상태에서 운동 종료를 시도한다.
2. 실제 RIR을 입력하고 한 세트 이상 완료한다.
3. 운동을 종료한다.
4. 대시보드와 기록 화면에서 방금 운동을 확인한다.
5. 새로고침 후 다시 확인한다.

기대 결과:

- 완료 세트가 없으면 완료 기록을 만들지 않고 진행 중 초안을 제거한 뒤 홈으로 돌아간다.
- 완료 세션의 상태, 목표 RIR, 실제 RIR이 저장된다.
- 대시보드와 기록 화면의 캐시가 즉시 갱신된다.
- 새로고침 후에도 완료 기록이 남아 있다.

### UF-06 루틴 생성과 저장

1. 새 루틴을 만들고 이름을 입력한다.
2. 종목을 추가한다.
3. 세트별 중량, 반복 범위, 유형, 목표 RIR, 휴식 시간을 입력한다.
4. 본세트 목표 RIR을 일괄 적용한다.
5. 저장한다.

기대 결과:

- 필수 입력이 없으면 저장되지 않는다.
- 각 세트의 유형을 웜업·본세트·탑세트·백오프·드롭 중에서 지정할 수 있고, 본세트에만 일괄 RIR이 적용된다.
- 저장 안내가 표시되고 목록 및 운동 시작 화면에 새 루틴이 나타난다.
- 새로고침 후에도 저장한 루틴이 남아 있다.

### UF-07 저장하지 않은 루틴 편집 보호

1. 기존 루틴의 이름 또는 세트 값을 수정한다.
2. 다른 루틴 선택, 새 루틴 생성, 모바일 목록 복귀를 시도한다.
3. 이탈을 취소한 뒤 값을 확인한다.
4. 다시 이탈을 시도하고 승인한다.

기대 결과:

- 저장하지 않은 변경이 있으면 접근 가능한 확인 대화상자가 표시된다.
- 취소 시 편집값이 유지된다.
- 이탈 승인 시 선택한 다음 행동이 수행된다.
- 저장 성공 후에는 불필요한 확인이 표시되지 않는다.

### UF-08 기록 탭: 달력·날짜별 목록·상세

1. `/records`로 이동한다.
2. 달력에서 운동한 날을 누른다.
3. 그 날의 기록 목록에서 하나를 눌러 상세로 들어간다.
4. 상세에서 `공유`를 열어 실제 RIR 표시를 켜고 끄고, PNG 저장과 공유하기를 실행한다.
5. 되돌아가기로 목록으로 돌아온다.

기대 결과:

- 기록 탭은 달력과 **선택한 날의 기록 목록**만 보여준다. 세트 값은 상세에서 본다. **(자동 테스트 검증)**
- 날짜를 고르지 않고 들어오면 가장 최근에 운동한 날이 열린다. 오늘로 열면 대부분의 방문이 빈 목록으로 시작한다. **(자동 테스트 검증)**
- 하루에 두 번 운동한 날은 두 기록이 **모두** 목록에 나온다. **(자동 테스트 검증)**
- 운동이 없는 날을 `?d=`로 직접 열면 "이 날에는 완료한 운동이 없어요."를 보여준다.
- 목록에서 기록을 누르면 `/records/:sessionId` 전용 상세 페이지로 이동한다. **(자동 테스트 검증)**
- 상세의 완료 세트에는 저장된 웜업·본세트·탑세트·백오프·드롭 유형이 표시된다. **(자동 테스트 검증)**
- 상세의 되돌아가기는 보고 있던 날짜(`/records?d=YYYY-MM-DD`)로 돌아간다. 날짜가 초기화되지 않는다. **(자동 테스트 검증)**
- 상세의 `공유`·`수정`·`삭제` 버튼은 390px에서도 한 줄에 들어간다.
- 선택한 세션과 상세/공유 카드 내용이 일치한다.
- RIR 5 이상은 `5+`로 일관되게 표시된다.
- RIR을 끄면 요약 카드가 빈 열 없이 재배치된다.
- 공유 카드의 각 종목명 아래에는 그 세션에서 완료한 세트 중 가장 높은 예상 1RM(Brzycki)이 함께 표시된다. 여러 완료 세트 중 가장 무거운 세트가 아니라 e1RM이 가장 높은 세트 기준이다.
- 체중 운동(기록된 중량 없음), 완료 세트가 모두 반복 상한(12회)을 넘는 종목 등 추정치를 계산할 수 없는 경우에는 0이나 대시 없이 그 줄 자체가 표시되지 않는다.
- PNG 결과는 화면 폭과 무관하게 일정한 출력 크기와 현지 날짜 파일명을 가지며, 예상 1RM 줄이 추가되어 카드가 길어져도 동일하게 동작한다.
- 파일 공유를 지원하지 않거나 공유가 실패하면 PNG 다운로드로 안전하게 대체된다.

### UF-09 자유 운동과 진행 중 종목 관리

1. `자유 운동으로 시작`으로 빈 세션을 연다.
2. 종목을 추가하지 않은 채 `운동 종료`를 누른다.
3. 자유 운동을 다시 열고 `종목 추가`로 시트를 열어 두 종목을 추가한다.
4. `순서 변경` 모달에서 드래그앤드롭 또는 위/아래 버튼으로 순서를 바꾼다.
5. 한 종목을 삭제하고 남은 종목의 세트를 완료한 뒤 운동을 종료한다.

기대 결과:

- 빈 세션은 완료 기록이나 공유 대상에 남지 않는다.
- 순서 변경은 저장된 초안과 재개한 운동 화면에 유지된다.
- 모든 종목의 세트가 화면에 항상 펼쳐진 채로 함께 나열되며, 종목을 선택해 들어가는 과정 없이 바로 기록할 수 있다.
- 종목 삭제 후 남은 종목의 세트가 그대로 이어서 보인다.
- 삭제하지 않은 종목과 완료한 세트만 최종 기록에 저장된다.

### UF-15 종목 추가 시트 검색·필터와 즉석 운동 생성

1. 자유 운동에서 `종목 추가`로 시트를 연다.
2. 운동 이름으로 검색한다.
3. 부위 필터와 장비 필터를 각각 적용한다.

- 새 운동을 저장하면 운동 카탈로그에 반영되고, 목록에서 다시 찾지 않아도 진행 중인 운동에 즉시 추가된다. **(자동 테스트 검증)**
- 다이얼로그를 취소해도 아래 시트는 검색/필터/선택이 계속 정상 동작한다. **(자동 테스트 검증)**
- Esc는 가장 위에 열린 레이어부터 하나씩 닫는다(다이얼로그 → 시트 순). **(자동 테스트 검증)**
- 바깥 영역 클릭으로도 가장 위에 열린 레이어가 닫힌다.
- 맨몸 장비 종목은 중량 입력란이 "추가 중량"으로 표시되고, 비워 두어도 결측처럼 보이지 않는다(플레이스홀더로 "맨몸" 표시). 그 외 장비는 기존과 동일하게 "중량"으로 표시된다.

### UF-16 운동 일시정지

1. 자유 운동을 시작하고 잠시 기다려 경과 시간이 흐르는 것을 확인한다.
2. 헤더의 일시정지 버튼을 눌러 운동을 멈춘다.
3. 시간이 흐르는 동안(전화, 기구 대기 등을 흉내 낸다) 경과 시간 표시가 멈춰 있는지 확인한다.
4. 재개 버튼을 눌러 운동을 이어간다.
5. 일시정지 중에도 세트 완료/휴식 타이머는 정상 동작하는지 확인한다.
6. 일시정지한 채로 화면을 벗어났다가(다른 메뉴 이동 또는 새로고침) 다시 운동 화면으로 돌아온다.
7. 세트를 하나 이상 완료한 뒤 운동을 종료하고, 기록/대시보드에서 소요 시간을 확인한다.

기대 결과:

- 일시정지 중에는 러너 헤더의 경과 시간이 더 이상 늘어나지 않는다. **(자동 테스트 검증)**
- 재개하면 일시정지가 시작된 지점부터 이어서 흐르고, 일시정지한 구간만큼 건너뛰지 않는다. **(자동 테스트 검증)**
- 일시정지 상태는 시계 배지 색상 변화와 "일시정지" 배지로 눈에 띄게 표시되고, 재개 토스트에도 같은 계산으로 반영된다(재개 토스트를 직접 렌더링해 검증하는 자동 테스트는 아직 없다).
- 일시정지 중에도 세트 완료와 휴식 타이머는 그대로 동작한다(일시정지는 운동 시계에만 적용되고 화면 전체를 멈추지 않는다).
- 일시정지한 채로 새로고침해도 경과 시간이 일시정지 시작 시점에 멈춰 있다(실제로 얼마나 시간이 흘렀든 그 공백을 흡수하지 않는다). **(자동 테스트 검증)**
- 일시정지 필드가 없는(이 기능 이전에 저장된) 진행 중 초안도 그대로 복원되며, 일시정지 누적 시간은 0으로 취급된다. **(자동 테스트 검증)**
- 운동 종료 시 누적된 일시정지 시간이 세션에 저장되고, 기록/대시보드의 소요 시간 표시에서 그만큼 제외된다. **(자동 테스트 검증)**

### UF-17 주간 통계

1. `/stats`로 이동한다.
2. 이전/다음 주 버튼으로 여러 주를 오간다.
3. 완료한 운동이 있는 주와 없는 주를 각각 확인한다.
4. 지난주 기록이 없는 주와 있는 주에서 전주 대비 비교 문구를 확인한다.
5. 이번 주보다 미래로 이동을 시도한다.

기대 결과:

- 화면은 한 번에 한 주만 보여주며, 이전/다음 주 이동에 따라 제목의 기간 표기와 총 볼륨·요일별·부위별 내용이 함께 바뀐다. **(자동 테스트 검증)**
- 총 볼륨은 완료한 세트의 중량 × 반복 수 합계와 일치한다. **(자동 테스트 검증)**
- 이번 주보다 미래로는 이동할 수 없으며, 다음 주 버튼은 현재 주에서 비활성화된다. **(자동 테스트 검증)**
- 전주 대비 비교는 지난주 볼륨이 0이어도 `Infinity`나 `NaN`을 표시하지 않고 "지난주 기록이 없어 비교할 수 없어요."로 안내한다. **(자동 테스트 검증)**
- 지난주 볼륨이 있으면 증가/감소 방향과 퍼센트가 정확히 계산되어 표시된다. **(자동 테스트 검증)**
- 완료한 운동이 없는 주는 0이 나열된 표가 아니라 안내 문구가 있는 빈 상태 화면을 보여준다. **(자동 테스트 검증)**
- 부위별 분포는 각 종목의 `primaryMuscle` 기준으로 볼륨을 합산해 큰 순서로 나열된다. **(자동 테스트 검증)**
- 요일별 볼륨은 월요일 시작 기준으로 월~일 7일 모두 표시된다.

- 종목 선택 시트는 운동 진행 화면의 것을 그대로 재사용한다("새 운동 만들기" 버튼은 이 화면에서 생략된다). **(자동 테스트 검증)**
- 완료 기록이 여러 건이면 세션별 최고 중량 막대 차트와 각 세션의 예상 1RM(Brzycki 공식)을 함께 보여준다. **(자동 테스트 검증)**
- 예상 1RM은 Brzycki 공식(`중량 / (1.0278 - 0.0278 × 반복 수)`)으로 계산되며, 12회를 넘는 세트는 추정치를 표시하지 않는다(공식이 고반복에서 무너지기 때문). **(자동 테스트 검증)**
- 완료 기록이 한 건뿐이면 막대 차트 대신 그 한 건의 요약과 "비교할 이전 기록이 없어 추이를 표시할 수 없어요." 안내를 보여준다. **(자동 테스트 검증)**
- 기간 내 완료 기록이 없으면 빈 상태 안내를 보여준다. **(자동 테스트 검증)**
- 체중 운동(중량을 기록하지 않는 종목)은 중량과 예상 1RM 대신 세션별 최고 반복 수로 추이를 보여준다. **(자동 테스트 검증)**
- 조회 기간은 최근 180일로 고정되어 있으며, 세션 전체를 훑지 않는다.

### UF-19 기록 화면 월간 달력

1. `/records`로 이동한다.
2. 달력의 이전/다음 달 버튼으로 여러 달을 오간다.
3. 완료한 운동이 있는 날과 없는 날의 표시를 확인한다.
4. 완료한 운동이 전혀 없는 달로 이동한다.
5. 마킹된 날짜를 눌러 그 날의 기록 목록이 아래(데스크톱은 옆)에 열리는지 확인한다.
6. 연속 기록(스트릭)과 이 달 운동일 수치를 확인한다.
7. 모바일 너비(390px)에서 달력이 **펼쳐진 채로** 시작하는지, `달력 접기`로 접을 수 있는지 확인한다.

기대 결과:

- 달력은 완료한 세션이 있는 날짜만 표시하고, 그 외 날짜는 비어 있다. **(자동 테스트 검증)**
- 각 날짜 칸은 버튼이며, 접근 가능한 이름에 연/월/일과 운동 완료 여부("운동 완료"/"운동 기록 없음")가 포함된다 -- 채움 색만으로 구분되지 않는다. 운동 기록이 없는 날짜는 선택할 수 없도록 비활성화된다. **(자동 테스트 검증)**
- 이번 달보다 미래로는 이동할 수 없으며, 다음 달 버튼은 이번 달에서 비활성화된다. **(자동 테스트 검증)**
- 완료한 운동이 없는 달은 오류 화면이 아니라 "이 달에는 완료한 운동이 없어요." 안내를 보여준다. **(자동 테스트 검증)**
- 마킹된 날짜를 선택하면 그 날의 기록 목록이 열리고, 칸의 접근성 이름은 그 날 운동 횟수를 함께 읽어 준다(`운동 2회 완료`). 하루에 두 번 운동한 날도 두 기록이 모두 열린다. **(자동 테스트 검증)**
- 늦은 저녁이나 자정 직후에 기록한 세션도 UTC 날짜가 아니라 로컬 달력일 기준으로 정확한 칸에 표시된다. **(자동 테스트 검증)**
- 연속 기록은 자정에 끊긴 것으로 표시되지 않는다 -- 오늘 아직 운동을 완료하지 않았어도 어제까지 이어온 기록은 유지되며, "오늘 운동을 완료하면 계속 이어져요."로 안내한다. 오늘 운동을 완료하면 그만큼 늘어난다. **(자동 테스트 검증)**
- 연속 기록 조회는 세션 전체를 훑지 않고 최근 90일로 제한된다. 90일을 넘게 이어진 연속 기록은 실제보다 짧게 잘라 보여주는 대신 "90일 이상"으로 정직하게 표시한다. **(자동 테스트 검증)**
- 데스크톱 너비(1050px 이상)에서는 달력과 완료한 운동 목록이 왼쪽의 컴팩트한 탐색 열에 함께 있고, 선택한 기록 상세·공유 카드는 오른쪽 열에서 바로 확인할 수 있다. 달력은 화면 전체 폭을 차지하지 않아 날짜 칸이 과도하게 커지지 않는다.
- 모바일 너비(899px 이하)에서도 달력 grid는 **펼쳐진 채로** 시작한다. 달력이 날짜를 옮길 유일한 수단이 되었기 때문이다(예전에는 화면 아래 전체 목록으로도 다른 날에 갈 수 있어 접어 두었다). `달력 접기` 버튼으로 접으면 헤더와 요약 수치(연속 기록·이 달 운동일)만 남아 그 날의 목록을 위로 끌어올릴 수 있다.
- 날짜 칸의 탭 영역은 최소 36px 이상을 유지한다.

### UF-23 종목 관리와 사용자별 기본 카탈로그

1. 기존 사용자가 `/exercises`를 열어 기본 종목의 브랜드를 바꾸고 저장한다.
2. 저장한 종목을 보관한 뒤 보관함에서 다시 확인한다.
3. 새 계정으로 처음 로그인하고 기본 종목 목록을 확인한다.
4. 기존 루틴·운동 기록·1RM이 같은 이름의 사용자 소유 종목에 연결돼 있는지 확인한다.

기대 결과:

- 기본 종목을 포함해 화면에 보이는 모든 종목은 현재 사용자 소유이며 이름·브랜드·부위·장비·휴식 시간을 수정할 수 있다. **(mock 자동 테스트 검증)**
- 브랜드 변경 저장은 `406` 오류 없이 완료되고 목록 배지가 즉시 갱신된다. **(mock 자동 테스트 검증, 운영 Supabase 별도 확인)**
- 새 프로필에는 현재 시스템 기본 종목이 사용자 소유 복제본으로 한 번만 생성된다.
- 다른 사용자의 종목과 시스템 템플릿은 조회·수정할 수 없다.
- 기존 루틴·운동 기록·1RM은 사용자 소유 복제본으로 연결되며 기록과 통계가 끊기지 않는다.

### UF-25 운동 기록 삭제

1. `/records/:sessionId`로 완료 기록을 직접 연다.
2. 상세 패널의 `삭제`를 누른다.
3. 확인 대화상자에서 취소한 뒤 기록이 남아 있는지 확인한다.
4. 다시 삭제를 열어 `삭제하기`를 누른다.

기대 결과:

- 삭제 전에는 되돌릴 수 없음을 분명히 안내하는 접근 가능한 확인 대화상자가 열린다.
- 취소하면 어떤 데이터도 변경되지 않는다.
- 삭제하면 운동 세션과 연결된 종목·세트가 함께 제거되고, 삭제한 상세 URL은 더 이상 남지 않는다. **(자동 테스트 검증)**
- 기록 목록·달력·대시보드·주간 통계·종목별 지난 기록 캐시가 함께 갱신된다.
- 삭제 실패 시 기존 기록은 화면에 유지되고 재시도할 수 있다.

### UF-26 완료된 운동 기록 편집

1. `/records/:sessionId`로 완료 기록을 직접 연다.
2. 상세 패널의 `수정`을 눌러 `/records/:sessionId/edit`으로 이동한다.
3. 세트의 중량·횟수(유산소는 시간·거리)와 실제 RIR을 고친다.
4. `세트 추가`로 세트를 하나 더하고, 세트 하나를 삭제한다.
5. 운동 메모를 고친다.
6. `취소`를 눌러 확인 대화상자를 확인한 뒤 `계속 편집`으로 돌아온다.
7. `저장하기`를 누른다.

기대 결과:

- 편집 화면에는 **완료된 세트만** 보인다. 기록 상세와 같은 기준이며, 완료되지 않은 세트는 화면에 나타나지 않지만 저장해도 사라지지 않는다.
- 목표 RIR은 읽기 전용이다. 종목 구성과 운동 시작·종료 시각은 편집 대상이 아니다.
- 세트를 삭제하면 남은 세트 번호가 1부터 다시 매겨진다. **(자동 테스트 검증)**
- 종목에 완료 세트가 하나만 남으면 그 세트의 삭제 버튼은 비활성화된다 -- 완료 세트가 0개가 되면 종목이 기록에서 통째로 사라지는데, 그건 세트 삭제가 아니라 종목 삭제이므로 이 화면의 범위가 아니다. **(자동 테스트 검증)**
- 더한 세트의 완료 시각은 지금이 아니라 그 운동의 완료 시각이다. 3일 전 운동에 오늘 날짜가 박히지 않는다.
- 고친 내용이 있는 상태에서 `취소`를 누르거나 사이드바·하단 탭으로 다른 화면으로 나가려 하면 확인을 받는다. 고친 것이 없으면 확인 없이 바로 상세로 돌아간다. **(자동 테스트 검증)**
- 고친 것이 없으면 `저장하기`는 비활성 상태로 보인다.
- 저장하면 기록 상세로 돌아가고 고친 값이 반영된다. 기록 목록·달력·대시보드·주간 통계·종목별 지난 기록 캐시가 함께 갱신된다. **(자동 테스트 검증)**
- 저장한 기록에는 `수정됨` 표시가 붙는다. **(자동 테스트 검증 -- mock 어댑터 기준. 실제 DB는 `20260827090000_workout_session_edited_at.sql`을 적용해야 표시된다.)**
- 저장 실패 시 편집 내용은 화면에 유지되고 재시도할 수 있다.

### UF-30 운동 시작 전 초기 작업 중량

1. 운동 시작에서 개인 루틴을 선택하고 `시작`을 누른다.
2. 종목별 초기 작업 중량 제안값을 확인하고 하나 이상의 값을 수정한다.
3. `이 중량으로 시작`을 눌러 운동 화면의 세트 값을 확인한다.
4. 프로그램의 웨이트 Day를 시작해 1RM 계산값 또는 고정 처방값이 제안되는지 확인한다.
5. 맨몸 또는 유산소 종목만 있는 운동은 중량 확인 단계 없이 시작되는지 확인한다.

기대 결과:

- 바벨·덤벨·머신·케이블 등 중량을 기록하는 종목만 시작 전 확인 목록에 나타난다. 빈 값이 있으면 시작할 수 없다. **(자동 테스트 검증)**
- 루틴 고정 중량과 프로그램의 1RM 계산/고정 중량이 제안값으로 채워진다. 사용자가 값을 바꾸면 운동 초안의 세트 입력값에 반영된다. **(자동 테스트 검증)**
- 세트마다 처방 중량이 다른 경우 첫 작업 중량의 변경 폭만큼 함께 조정되어 웜업·백오프의 차이가 유지된다. **(단위 테스트 검증)**
- 맨몸·유산소 종목은 초기 중량 입력을 요구하지 않는다. **(단위 테스트 검증)**
- 이 값은 시작할 운동 초안에만 적용하므로 루틴·프로그램 스냅샷이나 원격 DB를 변경하지 않는다.
