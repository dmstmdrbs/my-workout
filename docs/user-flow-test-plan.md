# Trainlog 사용자 플로우 테스트 계획

현재 검증 범위는 `localStorage` 기반 mock adapter를 사용하는 웹앱이다. Supabase와 Google 로그인은 adapter 연결 이후 별도 시나리오로 검증한다.

## 공통 합격 기준

- 화면 전환 중 입력 데이터가 의도치 않게 사라지지 않는다.
- 목표 RIR과 실제 RIR은 별도 값으로 유지된다.
- 저장 성공 후 새로고침해도 루틴과 완료 운동이 남아 있다.
- 실패하거나 비어 있는 상태에서 사용자가 다음 행동을 알 수 있다.
- 데스크톱과 모바일에서 핵심 행동이 가려지거나 조작 불가능하지 않다.

## 시나리오

### UF-01 대시보드 진입과 메뉴 이동

1. 저장소를 초기화하고 앱을 연다.
2. 주간 지표, 최근 운동, 내 루틴을 확인한다.
3. 대시보드, 운동 시작, 루틴, 기록 메뉴를 차례로 연다.
4. `전체 보기`, `관리`, 최근 기록 행, 루틴 행, 상단 더보기 메뉴를 연다.

기대 결과:

- 시드 데이터가 오류 없이 렌더링된다.
- 선택된 메뉴가 명확히 표시된다.
- `전체 보기`와 최근 기록 행은 기록 화면으로 이동하며, 행에서 선택한 기록이 열린다.
- `관리`와 루틴 행은 루틴 화면으로 이동하며, 행에서 선택한 루틴이 열린다.
- 상단 더보기 메뉴에서 통계와 설정 화면으로 이동할 수 있다.
- 기능이 없는 버튼은 동작하는 것처럼 노출되지 않는다.

### UF-02 루틴을 선택해 운동 시작

1. 운동 시작 화면을 연다.
2. `Pull Day`를 선택하고 시작한다.
3. 첫 종목의 목표 중량, 반복 수, 목표 RIR을 확인한다.

기대 결과:

- 루틴 처방이 운동 초안으로 복제된다.
- 실제 RIR은 선택 전까지 미기록 상태다.
- 목표 RIR은 실제 RIR 입력으로 변경되지 않는다.

### UF-03 세트 기록과 휴식 타이머

1. 첫 세트의 중량과 반복 수를 변경한다.
2. 실제 RIR을 선택한다.
3. 세트를 완료하고 다시 완료를 취소한다.
4. 작업 세트를 추가한다.

기대 결과:

- 입력값과 실제 RIR이 초안에 반영된다.
- 세트 완료 시 휴식 타이머가 시작된다.
- 완료 취소가 가능하다.
- 추가 세트는 처방값을 복제하지만 실제 RIR은 미기록 상태다.

### UF-04 진행 중 운동 보존과 이탈 보호

1. 세트 값을 입력한 상태에서 다른 메뉴로 이동한다.
2. 이탈을 취소한 뒤 입력값이 남아 있는지 확인한다.
3. 이탈을 승인하고 다시 운동 화면을 연다.
4. 별도 실행에서는 입력 후 새로고침한다.

기대 결과:

- 우발적인 메뉴 이동에는 확인 절차가 제공된다.
- 이탈 취소 시 초안이 유지된다.
- 새로고침 후 진행 중 초안을 복원할 수 있다.
- 명시적 취소 시 임시 초안이 제거된다.

### UF-05 운동 완료와 기록 반영

1. 완료 세트가 없는 상태에서 운동 종료를 시도한다.
2. 실제 RIR을 입력하고 한 세트 이상 완료한다.
3. 운동을 종료한다.
4. 대시보드와 기록 화면에서 방금 운동을 확인한다.
5. 새로고침 후 다시 확인한다.

기대 결과:

- 완료 세트가 없으면 완료 기록을 만들지 않고 진행 중 초안을 제거한 뒤 홈으로 돌아간다.
- 완료 세션의 상태, 목표 RIR, 실제 RIR이 저장된다.
- 대시보드와 기록 화면의 캐시가 즉시 갱신된다.
- 새로고침 후에도 완료 기록이 남아 있다.

### UF-06 루틴 생성과 저장

1. 새 루틴을 만들고 이름을 입력한다.
2. 종목을 추가한다.
3. 세트별 중량, 반복 범위, 유형, 목표 RIR, 휴식 시간을 입력한다.
4. 작업 세트 목표 RIR을 일괄 적용한다.
5. 저장한다.

기대 결과:

- 필수 입력이 없으면 저장되지 않는다.
- 작업 세트에만 일괄 RIR이 적용된다.
- 저장 안내가 표시되고 목록 및 운동 시작 화면에 새 루틴이 나타난다.
- 새로고침 후에도 저장한 루틴이 남아 있다.

### UF-07 저장하지 않은 루틴 편집 보호

1. 기존 루틴의 이름 또는 세트 값을 수정한다.
2. 다른 루틴 선택, 새 루틴 생성, 모바일 목록 복귀를 시도한다.
3. 이탈을 취소한 뒤 값을 확인한다.
4. 다시 이탈을 시도하고 승인한다.

기대 결과:

- 저장하지 않은 변경이 있으면 접근 가능한 확인 대화상자가 표시된다.
- 취소 시 편집값이 유지된다.
- 이탈 승인 시 선택한 다음 행동이 수행된다.
- 저장 성공 후에는 불필요한 확인이 표시되지 않는다.

### UF-08 기록 상세와 공유 카드

1. 완료 기록을 선택한다.
2. 실제 RIR 표시를 켜고 끈다.
3. PNG 저장을 실행한다.
4. 공유하기를 실행한다.

기대 결과:

- 선택한 세션과 상세/공유 카드 내용이 일치한다.
- RIR 5 이상은 `5+`로 일관되게 표시된다.
- RIR을 끄면 요약 카드가 빈 열 없이 재배치된다.
- PNG 결과는 화면 폭과 무관하게 일정한 출력 크기와 현지 날짜 파일명을 가진다.
- 파일 공유를 지원하지 않거나 공유가 실패하면 PNG 다운로드로 안전하게 대체된다.

### UF-09 자유 운동과 진행 중 종목 관리

1. `자유 운동으로 시작`으로 빈 세션을 연다.
2. 종목을 추가하지 않은 채 `운동 종료`를 누른다.
3. 자유 운동을 다시 열고 두 종목을 추가한다.
4. `순서 변경` 모달에서 드래그앤드롭 또는 위/아래 버튼으로 순서를 바꾼다.
5. 한 종목을 삭제하고 남은 종목의 세트를 완료한 뒤 운동을 종료한다.

기대 결과:

- 빈 세션은 완료 기록이나 공유 대상에 남지 않는다.
- 순서 변경은 저장된 초안과 재개한 운동 화면에 유지된다.
- 모든 종목의 세트가 화면에 항상 펼쳐진 채로 함께 나열되며, 종목을 선택해 들어가는 과정 없이 바로 기록할 수 있다.
- 종목 삭제 후 남은 종목의 세트가 그대로 이어서 보인다.
- 삭제하지 않은 종목과 완료한 세트만 최종 기록에 저장된다.

### UF-10 반응형 핵심 조작성

데스크톱(1440px), 태블릿(768px), 모바일(390px)에서 UF-01, UF-03, UF-06, UF-08의 주요 화면을 확인한다.

기대 결과:

- 데스크톱에서는 사이드바와 다열 관리 화면을 사용한다.
- 운동 진행 화면은 데스크톱을 포함한 모든 화면 폭에서 종목 카드가 위아래로 쌓여 스크롤되는 단일 열 구성을 사용하며, 카드 폭은 지나치게 넓어지지 않도록 제한된다.
- 모바일에서는 하단 메뉴와 단일 열 편집 흐름을 사용한다.
- 휴식 타이머는 화면 폭과 무관하게 화면 하단에 고정되어 스크롤해도 계속 보이며, 마지막 세트와 완료 버튼을 가리지 않는다.
- 핵심 입력과 버튼이 가로 스크롤 없이 조작 가능하다.

### UF-11 URL 라우팅과 히스토리

1. `/records/session-2026-08-14`와 `/routines/pull-day` 주소로 직접 연다.
2. 대시보드에서 `전체 보기` 또는 행 링크로 이동한다.
3. 브라우저 뒤로가기를 실행한다.
4. 존재하지 않는 주소로 연다.

기대 결과:

- 직접 주소에서도 해당 기록 또는 루틴이 선택된 화면이 렌더링된다.
- 대시보드 링크는 `/records`, `/records/:sessionId`, `/routines`, `/routines/:routineId` 주소로 이동한다.
- 뒤로가기와 앞으로가기로 직전 화면 상태를 복원한다.
- 알 수 없는 경로는 대시보드로 안전하게 이동한다.

### UF-12 설정 변경과 로그아웃

1. `/settings`로 이동한다.
2. 테마를 다크로 바꾼다.
3. 기본 휴식 시간과 기본 목표 RIR을 바꾼다.
4. 자유 운동을 시작해 새 종목을 추가한다.
5. 설정으로 돌아와 로그아웃한다.
6. (선택 사항) 같은 기기에서 다른 계정으로 다시 로그인한다.

기대 결과:

- 테마 변경이 즉시 적용되고 새로고침 후에도 유지된다.
- 데이터베이스에 저장된 테마가 앱 시작 시 반영되므로, 로컬 저장소의 미러 값과 다르면 데이터베이스 값이 우선된다.
- 바뀐 기본 목표 RIR이 새로 추가한 종목의 세트에 반영된다.
- 표시 이름을 바꾸면 대시보드 인사말에 반영된다.
- 휴식 시간에 빈 값이나 음수를 넣으면 저장하지 않고 이전 값을 유지한다.
- 로그아웃하면 로그인 화면으로 돌아간다.
- 로그아웃하면 테마가 시스템으로 리셋되므로, 같은 기기에서 다음에 로그인한 계정은 자기 설정이 반영되기 전까지 기기 설정을 따른다.
- 진행 중 초안이 있으면 로그아웃 확인에 그 사실이 안내되고, 진행 시 초안과 재개 토스트가 사라진다.

### UF-13 신체 측정 기록

1. `/body`로 이동한다.
2. 체중만 입력해 저장한다.
3. 같은 날짜로 체지방률을 추가 입력해 저장한다.
4. 다른 날짜로 한 건 더 저장한다.
5. 메모만 입력하고 저장을 시도한다.
6. 기록 목록을 불러오는 중이거나 불러오지 못한 상태에서 저장을 시도한다.

기대 결과:

- 체중만 있는 기록도 저장되고 목록에 나타난다.
- 같은 날짜 재입력은 새 행을 만들지 않고 기존 행을 수정한다.
- 목록은 최근 날짜가 위에 온다.
- 수치를 하나도 입력하지 않으면 저장되지 않고 안내가 표시된다.
- 상단 더보기 메뉴에서 신체 기록으로 이동할 수 있다.
- 기존 기록 목록을 불러오는 동안에는 저장 버튼이 비활성화되고, "기존 기록을 불러오는 중이에요. 잠시 후 저장할 수 있어요."라는 안내가 표시된다.
- 기존 기록 목록 불러오기가 실패하면 저장 버튼이 비활성화되고, "기존 기록을 불러오지 못해 지금은 저장할 수 없어요. 아래에서 다시 시도해 주세요."라는 안내가 표시된다.
- 저장 후 입력 폼이 초기화되므로, 다시 저장하려면 새로운 수치를 입력해야 한다.

### UF-14 기록 화면 페이지네이션

1. `/records`로 이동한다.
2. 목록을 아래로 스크롤해 더 많은 기록을 불러온다.
3. 마지막 기록 근처까지 스크롤해 목록이 더 이상 늘어나지 않는지 확인한다.
4. 마지막 페이지에 없는 오래된 세션의 주소(`/records/:sessionId`)로 직접 진입한다.
5. 상세 화면에서 앞 페이지로 돌아가 목록을 다시 스크롤한다.

기대 결과:

- 목록은 최근 기록 순서로 처음 20개를 로드한다. **(자동 테스트 검증)**
- 목록 하단을 관찰 중이며, 화면 진입 시 다음 페이지가 자동으로 붙는다. **(자동 테스트 검증)**
- 마지막 페이지는 20개 미만의 항목을 가지므로, 더 이상 새로운 항목이 추가되지 않는다. **(자동 테스트 검증)**
- 목록에 없는 세션을 직접 주소로 열 수 있으며, 상세 화면이 정상 렌더링된다. **(자동 테스트 검증)**
- 존재하지 않거나 삭제된 세션 id로 직접 진입하면(단건 조회가 `null`을 반환하면), 다른 세션이 대신 보이지 않고 "기록을 찾을 수 없어요." 화면이 표시된다. **(자동 테스트 검증)**
- 목록과 상세 화면 간의 이동과 스크롤이 부드럽고, 캐시된 데이터가 일관성 있게 유지된다. **(수동 확인)**

**수동 확인 불가 항목 (실제 DB 필요):**
- 저장 도중 네트워크를 끊었을 때 부분 저장이 남지 않는지 (세션만 있고 세트가 없는 상태): RPC 트랜잭션 특성상 자동 테스트로 검증 불가능하며, 운영 환경에서 Supabase 마이그레이션 적용 후 수동 확인 필요
