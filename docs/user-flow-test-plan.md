# Trainlog 사용자 플로우 테스트 계획

현재 검증 범위는 `localStorage` 기반 mock adapter를 사용하는 웹앱이다. Supabase와 Google 로그인은 adapter 연결 이후 별도 시나리오로 검증한다.

## 공통 합격 기준

- 화면 전환 중 입력 데이터가 의도치 않게 사라지지 않는다.
- 목표 RIR과 실제 RIR은 별도 값으로 유지된다.
- 저장 성공 후 새로고침해도 루틴과 완료 운동이 남아 있다.
- 실패하거나 비어 있는 상태에서 사용자가 다음 행동을 알 수 있다.
- 데스크톱과 모바일에서 핵심 행동이 가려지거나 조작 불가능하지 않다.

## 시나리오

### UF-01 대시보드 진입과 메뉴 이동

1. 저장소를 초기화하고 앱을 연다.
2. 주간 지표, 최근 운동, 내 루틴을 확인한다.
3. 대시보드, 운동 시작, 루틴, 기록 메뉴를 차례로 연다.
4. `전체 보기`, `관리`, 최근 기록 행, 루틴 행, 상단 더보기 메뉴를 연다.

기대 결과:

- 시드 데이터가 오류 없이 렌더링된다.
- 선택된 메뉴가 명확히 표시된다.
- `전체 보기`와 최근 기록 행은 기록 화면으로 이동하며, 행에서 선택한 기록이 열린다.
- `관리`와 루틴 행은 루틴 화면으로 이동하며, 행에서 선택한 루틴이 열린다.
- 상단 더보기 메뉴에서 통계와 설정 화면으로 이동할 수 있다.
- 기능이 없는 버튼은 동작하는 것처럼 노출되지 않는다.

### UF-02 루틴을 선택해 운동 시작

1. 운동 시작 화면을 연다.
2. `Pull Day`를 선택하고 시작한다.
3. 첫 종목의 목표 중량, 반복 수, 목표 RIR을 확인한다.

기대 결과:

- 루틴 처방이 운동 초안으로 복제된다.
- 실제 RIR은 선택 전까지 미기록 상태다.
- 목표 RIR은 실제 RIR 입력으로 변경되지 않는다.

### UF-03 세트 기록과 휴식 타이머

1. 첫 세트의 중량과 반복 수를 변경한다.
2. 실제 RIR을 선택한다.
3. 세트를 완료하고 다시 완료를 취소한다.
4. 작업 세트를 추가한다.

기대 결과:

- 입력값과 실제 RIR이 초안에 반영된다.
- 세트 완료 시 휴식 타이머가 시작된다.
- 완료 취소가 가능하다.
- 추가 세트는 처방값을 복제하지만 실제 RIR은 미기록 상태다.

### UF-04 진행 중 운동 보존과 이탈 보호

1. 세트 값을 입력한 상태에서 다른 메뉴로 이동한다.
2. 이탈을 취소한 뒤 입력값이 남아 있는지 확인한다.
3. 이탈을 승인하고 다시 운동 화면을 연다.
4. 별도 실행에서는 입력 후 새로고침한다.

기대 결과:

- 우발적인 메뉴 이동에는 확인 절차가 제공된다.
- 이탈 취소 시 초안이 유지된다.
- 새로고침 후 진행 중 초안을 복원할 수 있다.
- 명시적 취소 시 임시 초안이 제거된다.

### UF-05 운동 완료와 기록 반영

1. 완료 세트가 없는 상태에서 운동 종료를 시도한다.
2. 실제 RIR을 입력하고 한 세트 이상 완료한다.
3. 운동을 종료한다.
4. 대시보드와 기록 화면에서 방금 운동을 확인한다.
5. 새로고침 후 다시 확인한다.

기대 결과:

- 완료 세트가 없으면 완료 기록을 만들지 않고 진행 중 초안을 제거한 뒤 홈으로 돌아간다.
- 완료 세션의 상태, 목표 RIR, 실제 RIR이 저장된다.
- 대시보드와 기록 화면의 캐시가 즉시 갱신된다.
- 새로고침 후에도 완료 기록이 남아 있다.

### UF-06 루틴 생성과 저장

1. 새 루틴을 만들고 이름을 입력한다.
2. 종목을 추가한다.
3. 세트별 중량, 반복 범위, 유형, 목표 RIR, 휴식 시간을 입력한다.
4. 작업 세트 목표 RIR을 일괄 적용한다.
5. 저장한다.

기대 결과:

- 필수 입력이 없으면 저장되지 않는다.
- 작업 세트에만 일괄 RIR이 적용된다.
- 저장 안내가 표시되고 목록 및 운동 시작 화면에 새 루틴이 나타난다.
- 새로고침 후에도 저장한 루틴이 남아 있다.

### UF-07 저장하지 않은 루틴 편집 보호

1. 기존 루틴의 이름 또는 세트 값을 수정한다.
2. 다른 루틴 선택, 새 루틴 생성, 모바일 목록 복귀를 시도한다.
3. 이탈을 취소한 뒤 값을 확인한다.
4. 다시 이탈을 시도하고 승인한다.

기대 결과:

- 저장하지 않은 변경이 있으면 접근 가능한 확인 대화상자가 표시된다.
- 취소 시 편집값이 유지된다.
- 이탈 승인 시 선택한 다음 행동이 수행된다.
- 저장 성공 후에는 불필요한 확인이 표시되지 않는다.

### UF-08 기록 상세와 공유 카드

1. 완료 기록을 선택한다.
2. 실제 RIR 표시를 켜고 끈다.
3. PNG 저장을 실행한다.
4. 공유하기를 실행한다.

기대 결과:

- 선택한 세션과 상세/공유 카드 내용이 일치한다.
- RIR 5 이상은 `5+`로 일관되게 표시된다.
- RIR을 끄면 요약 카드가 빈 열 없이 재배치된다.
- PNG 결과는 화면 폭과 무관하게 일정한 출력 크기와 현지 날짜 파일명을 가진다.
- 파일 공유를 지원하지 않거나 공유가 실패하면 PNG 다운로드로 안전하게 대체된다.

### UF-09 자유 운동과 진행 중 종목 관리

1. `자유 운동으로 시작`으로 빈 세션을 연다.
2. 종목을 추가하지 않은 채 `운동 종료`를 누른다.
3. 자유 운동을 다시 열고 `종목 추가`로 시트를 열어 두 종목을 추가한다.
4. `순서 변경` 모달에서 드래그앤드롭 또는 위/아래 버튼으로 순서를 바꾼다.
5. 한 종목을 삭제하고 남은 종목의 세트를 완료한 뒤 운동을 종료한다.

기대 결과:

- 빈 세션은 완료 기록이나 공유 대상에 남지 않는다.
- 순서 변경은 저장된 초안과 재개한 운동 화면에 유지된다.
- 모든 종목의 세트가 화면에 항상 펼쳐진 채로 함께 나열되며, 종목을 선택해 들어가는 과정 없이 바로 기록할 수 있다.
- 종목 삭제 후 남은 종목의 세트가 그대로 이어서 보인다.
- 삭제하지 않은 종목과 완료한 세트만 최종 기록에 저장된다.

### UF-10 반응형 핵심 조작성

데스크톱(1440px), 태블릿(768px), 모바일(390px)에서 UF-01, UF-03, UF-06, UF-08의 주요 화면을 확인한다.

기대 결과:

- 데스크톱에서는 사이드바와 다열 관리 화면을 사용한다.
- 운동 진행 화면은 데스크톱을 포함한 모든 화면 폭에서 종목 카드가 위아래로 쌓여 스크롤되는 단일 열 구성을 사용하며, 카드 폭은 지나치게 넓어지지 않도록 제한된다.
- 모바일에서는 하단 메뉴와 단일 열 편집 흐름을 사용한다.
- 휴식 타이머는 화면 폭과 무관하게 화면 하단에 고정되어 스크롤해도 계속 보이며, 마지막 세트와 완료 버튼을 가리지 않는다.
- 핵심 입력과 버튼이 가로 스크롤 없이 조작 가능하다.

### UF-11 URL 라우팅과 히스토리

1. `/records/session-2026-08-14`와 `/routines/pull-day` 주소로 직접 연다.
2. 존재하지 않거나 삭제된 루틴 id(예: `/routines/not-a-real-routine`)로 직접 연다.
3. 대시보드에서 `전체 보기` 또는 행 링크로 이동한다.
4. 브라우저 뒤로가기를 실행한다.
5. 존재하지 않는 주소로 연다.

기대 결과:

- 직접 주소에서도 해당 기록 또는 루틴이 선택된 화면이 렌더링된다.
- 대시보드 링크는 `/records`, `/records/:sessionId`, `/routines`, `/routines/:routineId` 주소로 이동한다.
- 뒤로가기와 앞으로가기로 직전 화면 상태를 복원한다.
- 존재하지 않거나 삭제된 루틴 id로 직접 진입하면, 다른 루틴이 대신 선택되지 않고 "루틴을 찾을 수 없어요." 화면이 표시된다. **(자동 테스트 검증)**
- 알 수 없는 경로는 대시보드로 리다이렉트되지 않는다. 입력한 주소가 그대로 유지된 채 "이 페이지를 찾을 수 없어요." 화면이 표시되고, 홈으로 돌아가는 버튼을 제공한다. **(자동 테스트 검증)**

### UF-12 설정 변경과 로그아웃

1. `/settings`로 이동한다.
2. 테마를 다크로 바꾼다.
3. 기본 휴식 시간과 기본 목표 RIR을 바꾼다.
4. 자유 운동을 시작해 종목 추가 시트로 새 종목을 추가한다.
5. 설정으로 돌아와 로그아웃한다.
6. (선택 사항) 같은 기기에서 다른 계정으로 다시 로그인한다.

기대 결과:

- 테마 변경이 즉시 적용되고 새로고침 후에도 유지된다.
- 데이터베이스에 저장된 테마가 앱 시작 시 반영되므로, 로컬 저장소의 미러 값과 다르면 데이터베이스 값이 우선된다.
- 바뀐 기본 목표 RIR이 새로 추가한 종목의 세트에 반영된다.
- 표시 이름을 바꾸면 대시보드 인사말에 반영된다.
- 휴식 시간에 빈 값이나 음수를 넣으면 저장하지 않고 이전 값을 유지한다.
- 로그아웃하면 로그인 화면으로 돌아간다.
- 로그아웃하면 테마가 시스템으로 리셋되므로, 같은 기기에서 다음에 로그인한 계정은 자기 설정이 반영되기 전까지 기기 설정을 따른다.
- 진행 중 초안이 있으면 로그아웃 확인에 그 사실이 안내되고, 진행 시 초안과 재개 토스트가 사라진다.

### UF-13 신체 측정 기록

1. `/body`로 이동한다.
2. 체중만 입력해 저장한다.
3. 같은 날짜로 체지방률을 추가 입력해 저장한다.
4. 다른 날짜로 한 건 더 저장한다.
5. 메모만 입력하고 저장을 시도한다.
6. 기록 목록을 불러오는 중이거나 불러오지 못한 상태에서 저장을 시도한다.

기대 결과:

- 체중만 있는 기록도 저장되고 목록에 나타난다.
- 같은 날짜 재입력은 새 행을 만들지 않고 기존 행을 수정한다.
- 목록은 최근 날짜가 위에 온다.
- 수치를 하나도 입력하지 않으면 저장되지 않고 안내가 표시된다.
- 상단 더보기 메뉴에서 신체 기록으로 이동할 수 있다.
- 기존 기록 목록을 불러오는 동안에는 저장 버튼이 비활성화되고, "기존 기록을 불러오는 중이에요. 잠시 후 저장할 수 있어요."라는 안내가 표시된다.
- 기존 기록 목록 불러오기가 실패하면 저장 버튼이 비활성화되고, "기존 기록을 불러오지 못해 지금은 저장할 수 없어요. 아래에서 다시 시도해 주세요."라는 안내가 표시된다.
- 저장 후 입력 폼이 초기화되므로, 다시 저장하려면 새로운 수치를 입력해야 한다.

### UF-14 기록 화면 페이지네이션

1. `/records`로 이동한다.
2. 목록을 아래로 스크롤해 더 많은 기록을 불러온다.
3. 마지막 기록 근처까지 스크롤해 목록이 더 이상 늘어나지 않는지 확인한다.
4. 마지막 페이지에 없는 오래된 세션의 주소(`/records/:sessionId`)로 직접 진입한다.
5. 상세 화면에서 앞 페이지로 돌아가 목록을 다시 스크롤한다.

기대 결과:

- 목록은 최근 기록 순서로 처음 20개를 로드한다. **(자동 테스트 검증)**
- 목록 하단을 관찰 중이며, 화면 진입 시 다음 페이지가 자동으로 붙는다. **(자동 테스트 검증)**
- 마지막 페이지는 20개 미만의 항목을 가지므로, 더 이상 새로운 항목이 추가되지 않는다. **(자동 테스트 검증)**
- 목록에 없는 세션을 직접 주소로 열 수 있으며, 상세 화면이 정상 렌더링된다. **(자동 테스트 검증)**
- 존재하지 않거나 삭제된 세션 id로 직접 진입하면(단건 조회가 `null`을 반환하면), 다른 세션이 대신 보이지 않고 "기록을 찾을 수 없어요." 화면이 표시된다. **(자동 테스트 검증)**
- 목록과 상세 화면 간의 이동과 스크롤이 부드럽고, 캐시된 데이터가 일관성 있게 유지된다. **(수동 확인)**

**수동 확인 불가 항목 (실제 DB 필요):**
- 저장 도중 네트워크를 끊었을 때 부분 저장이 남지 않는지 (세션만 있고 세트가 없는 상태): RPC 트랜잭션 특성상 자동 테스트로 검증 불가능하며, 운영 환경에서 Supabase 마이그레이션 적용 후 수동 확인 필요

### UF-15 종목 추가 시트 검색·필터와 즉석 운동 생성

1. 자유 운동에서 `종목 추가`로 시트를 연다.
2. 운동 이름으로 검색한다.
3. 부위 필터와 장비 필터를 각각 적용한다.
4. 찾는 운동이 없으면 시트의 `+`로 새 운동 만들기 다이얼로그를 연다.
5. 이름, 주요 부위, 장비, 기본 휴식 시간을 입력하고 저장한다.
6. 다이얼로그를 취소로 닫고 시트가 계속 정상 동작하는지 확인한다.
7. 다이얼로그가 열린 상태에서 Esc를 두 번 눌러 레이어가 순서대로 닫히는지 확인한다.
8. 맨몸(bodyweight) 장비인 종목을 추가해 세트의 중량 입력란을 확인한다.

기대 결과:

- 검색어, 부위 필터, 장비 필터는 각각 목록을 좁히며, 클라이언트에서 이미 불러온 카탈로그로 필터링한다. **(자동 테스트 검증)**
- 조건에 맞는 운동이 없으면 새로 만들라는 안내가 표시된다. **(자동 테스트 검증)**
- 시트와 새 운동 만들기 다이얼로그는 공용 오버레이 컴포넌트(포털 렌더링)로 뜨며, 다이얼로그는 시트 위에 겹쳐 뜬다.
- 새 운동을 저장하면 운동 카탈로그에 반영되고, 목록에서 다시 찾지 않아도 진행 중인 운동에 즉시 추가된다. **(자동 테스트 검증)**
- 다이얼로그를 취소해도 아래 시트는 검색/필터/선택이 계속 정상 동작한다. **(자동 테스트 검증)**
- Esc는 가장 위에 열린 레이어부터 하나씩 닫는다(다이얼로그 → 시트 순). **(자동 테스트 검증)**
- 바깥 영역 클릭으로도 가장 위에 열린 레이어가 닫힌다.
- 맨몸 장비 종목은 중량 입력란이 "추가 중량"으로 표시되고, 비워 두어도 결측처럼 보이지 않는다(플레이스홀더로 "맨몸" 표시). 그 외 장비는 기존과 동일하게 "중량"으로 표시된다.

### UF-16 운동 일시정지

1. 자유 운동을 시작하고 잠시 기다려 경과 시간이 흐르는 것을 확인한다.
2. 헤더의 일시정지 버튼을 눌러 운동을 멈춘다.
3. 시간이 흐르는 동안(전화, 기구 대기 등을 흉내 낸다) 경과 시간 표시가 멈춰 있는지 확인한다.
4. 재개 버튼을 눌러 운동을 이어간다.
5. 일시정지 중에도 세트 완료/휴식 타이머는 정상 동작하는지 확인한다.
6. 일시정지한 채로 화면을 벗어났다가(다른 메뉴 이동 또는 새로고침) 다시 운동 화면으로 돌아온다.
7. 세트를 하나 이상 완료한 뒤 운동을 종료하고, 기록/대시보드에서 소요 시간을 확인한다.

기대 결과:

- 일시정지 중에는 러너 헤더의 경과 시간이 더 이상 늘어나지 않는다. **(자동 테스트 검증)**
- 재개하면 일시정지가 시작된 지점부터 이어서 흐르고, 일시정지한 구간만큼 건너뛰지 않는다. **(자동 테스트 검증)**
- 일시정지 상태는 시계 배지 색상 변화와 "일시정지" 배지로 눈에 띄게 표시되고, 재개 토스트에도 같은 계산으로 반영된다(재개 토스트를 직접 렌더링해 검증하는 자동 테스트는 아직 없다).
- 일시정지 중에도 세트 완료와 휴식 타이머는 그대로 동작한다(일시정지는 운동 시계에만 적용되고 화면 전체를 멈추지 않는다).
- 일시정지한 채로 새로고침해도 경과 시간이 일시정지 시작 시점에 멈춰 있다(실제로 얼마나 시간이 흘렀든 그 공백을 흡수하지 않는다). **(자동 테스트 검증)**
- 일시정지 필드가 없는(이 기능 이전에 저장된) 진행 중 초안도 그대로 복원되며, 일시정지 누적 시간은 0으로 취급된다. **(자동 테스트 검증)**
- 운동 종료 시 누적된 일시정지 시간이 세션에 저장되고, 기록/대시보드의 소요 시간 표시에서 그만큼 제외된다. **(자동 테스트 검증)**

### UF-17 주간 통계

1. `/stats`로 이동한다.
2. 이전/다음 주 버튼으로 여러 주를 오간다.
3. 완료한 운동이 있는 주와 없는 주를 각각 확인한다.
4. 지난주 기록이 없는 주와 있는 주에서 전주 대비 비교 문구를 확인한다.
5. 이번 주보다 미래로 이동을 시도한다.

기대 결과:

- 화면은 한 번에 한 주만 보여주며, 이전/다음 주 이동에 따라 제목의 기간 표기와 총 볼륨·요일별·부위별 내용이 함께 바뀐다. **(자동 테스트 검증)**
- 총 볼륨은 완료한 세트의 중량 × 반복 수 합계와 일치한다. **(자동 테스트 검증)**
- 이번 주보다 미래로는 이동할 수 없으며, 다음 주 버튼은 현재 주에서 비활성화된다. **(자동 테스트 검증)**
- 전주 대비 비교는 지난주 볼륨이 0이어도 `Infinity`나 `NaN`을 표시하지 않고 "지난주 기록이 없어 비교할 수 없어요."로 안내한다. **(자동 테스트 검증)**
- 지난주 볼륨이 있으면 증가/감소 방향과 퍼센트가 정확히 계산되어 표시된다. **(자동 테스트 검증)**
- 완료한 운동이 없는 주는 0이 나열된 표가 아니라 안내 문구가 있는 빈 상태 화면을 보여준다. **(자동 테스트 검증)**
- 부위별 분포는 각 종목의 `primaryMuscle` 기준으로 볼륨을 합산해 큰 순서로 나열된다. **(자동 테스트 검증)**
- 요일별 볼륨은 월요일 시작 기준으로 월~일 7일 모두 표시된다.

### UF-18 종목별 중량 추이

1. `/stats`에서 "운동 선택" 버튼으로 종목 추가 시트를 연다.
2. 최근 180일 내 완료 기록이 여러 건 있는 종목을 선택한다.
3. 완료 기록이 정확히 한 건뿐인 종목을 선택한다.
4. 최근 180일 내 완료 기록이 없는 종목을 선택한다.
5. 체중 운동(장비가 "맨몸")을 선택한다.

기대 결과:

- 종목 선택 시트는 운동 진행 화면의 것을 그대로 재사용한다("새 운동 만들기" 버튼은 이 화면에서 생략된다). **(자동 테스트 검증)**
- 완료 기록이 여러 건이면 세션별 최고 중량 막대 차트와 각 세션의 예상 1RM(Brzycki 공식)을 함께 보여준다. **(자동 테스트 검증)**
- 예상 1RM은 Brzycki 공식(`중량 / (1.0278 - 0.0278 × 반복 수)`)으로 계산되며, 12회를 넘는 세트는 추정치를 표시하지 않는다(공식이 고반복에서 무너지기 때문). **(자동 테스트 검증)**
- 완료 기록이 한 건뿐이면 막대 차트 대신 그 한 건의 요약과 "비교할 이전 기록이 없어 추이를 표시할 수 없어요." 안내를 보여준다. **(자동 테스트 검증)**
- 기간 내 완료 기록이 없으면 빈 상태 안내를 보여준다. **(자동 테스트 검증)**
- 체중 운동(중량을 기록하지 않는 종목)은 중량과 예상 1RM 대신 세션별 최고 반복 수로 추이를 보여준다. **(자동 테스트 검증)**
- 조회 기간은 최근 180일로 고정되어 있으며, 세션 전체를 훑지 않는다.

### UF-19 기록 화면 월간 달력

1. `/records`로 이동한다.
2. 달력의 이전/다음 달 버튼으로 여러 달을 오간다.
3. 완료한 운동이 있는 날과 없는 날의 표시를 확인한다.
4. 완료한 운동이 전혀 없는 달로 이동한다.
5. 마킹된 날짜를 눌러 그 날의 기록이 선택되는지 확인한다(같은 페이지에 로드된 세션과, 아직 로드되지 않은 다른 달의 세션 모두).
6. 연속 기록(스트릭)과 이 달 운동일 수치를 확인한다.
7. 모바일 너비(390px)에서 달력이 기본적으로 접혀 있는지, `달력 보기` 버튼으로 펼쳐지는지 확인한다.

기대 결과:

- 달력은 완료한 세션이 있는 날짜만 표시하고, 그 외 날짜는 비어 있다. **(자동 테스트 검증)**
- 각 날짜 칸은 버튼이며, 접근 가능한 이름에 연/월/일과 운동 완료 여부("운동 완료"/"운동 기록 없음")가 포함된다 -- 채움 색만으로 구분되지 않는다. 운동 기록이 없는 날짜는 선택할 수 없도록 비활성화된다. **(자동 테스트 검증)**
- 이번 달보다 미래로는 이동할 수 없으며, 다음 달 버튼은 이번 달에서 비활성화된다. **(자동 테스트 검증)**
- 완료한 운동이 없는 달은 오류 화면이 아니라 "이 달에는 완료한 운동이 없어요." 안내를 보여준다. **(자동 테스트 검증)**
- 마킹된 날짜를 선택하면 그 날의 세션이 상세 패널에 열린다. 목록에 아직 로드되지 않은 세션(다른 달, 다음 페이지)을 선택해도 `/records/:sessionId` 직접 진입과 같은 단건 조회 경로로 정상적으로 열린다. **(자동 테스트 검증)**
- 늦은 저녁이나 자정 직후에 기록한 세션도 UTC 날짜가 아니라 로컬 달력일 기준으로 정확한 칸에 표시된다. **(자동 테스트 검증)**
- 연속 기록은 자정에 끊긴 것으로 표시되지 않는다 -- 오늘 아직 운동을 완료하지 않았어도 어제까지 이어온 기록은 유지되며, "오늘 운동을 완료하면 계속 이어져요."로 안내한다. 오늘 운동을 완료하면 그만큼 늘어난다. **(자동 테스트 검증)**
- 연속 기록 조회는 세션 전체를 훑지 않고 최근 90일로 제한된다. 90일을 넘게 이어진 연속 기록은 실제보다 짧게 잘라 보여주는 대신 "90일 이상"으로 정직하게 표시한다. **(자동 테스트 검증)**
- 데스크톱 너비에서는 달력이 기본적으로 펼쳐져 있다.
- 모바일 너비(899px 이하)에서는 완료한 운동 목록이 화면의 주된 조작 대상이므로, 달력 grid는 기본적으로 접혀 있고 헤더와 요약 수치(연속 기록·이 달 운동일)만 보인다. `달력 보기` 버튼으로 펼치고 접을 수 있다.
- 날짜 칸의 탭 영역은 최소 36px 이상을 유지한다.
