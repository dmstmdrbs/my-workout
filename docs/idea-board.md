# Trainlog 아이디어 보드

이 문서는 이 대화에서 나온 Trainlog 아이디어의 단일 정리본이다. 사용자는 떠오르는 내용을 자유롭게 말하고, Codex는 의미를 보존하면서 항목을 나누고 연결해 이 문서에 누적한다.

- 마지막 갱신: 2026-08-30
- 마지막 발급 번호: `TL-I-004`
- 아이디어 삭제 원칙: 중복이거나 채택하지 않은 아이디어도 지우지 않고 `제외` 또는 `보류`로 남긴다.

## 상태 기준

| 상태 | 의미 |
|---|---|
| `수집` | 아이디어를 막 기록한 상태. 구체화 전이어도 된다. |
| `구체화` | 범위, 사용자 흐름, 근거 또는 선택이 더 필요하다. |
| `준비` | 구현 목표와 완료 기준이 충분히 분명하다. |
| `구현 중` | 별도 구현 작업으로 가져간 상태다. |
| `완료` | 구현과 필요한 검증을 마쳤다. |
| `보류` | 가치가 있지만 지금은 진행하지 않는다. |
| `제외` | 중복, 방향 변경 등의 이유로 진행하지 않기로 했다. |

## 아이디어 상세

각 아이디어는 다음 형식으로 누적한다. 사용자의 원래 의도가 흐려지지 않도록 `사용자 메모`를 먼저 남기고, 해석이나 제안은 별도 항목으로 구분한다.

### TL-I-001 — AI 맞춤 루틴 생성

- 상태: `수집`
- 분류: `수익화`
- 기록일: 2026-08-30
- 사용자 메모: 각 사용자가 자신의 생활 방식에 맞는 루틴을 직접 생성하고 수행할 수 있게 한다. 모바일에는 간단한 생성 경험을 제공하고, PC의 큰 화면에서는 AI 채팅과 Trainlog에 꼭 필요한 구조화 입력 UI를 함께 제공한다. 사용자 정보, 필요, 목표 등을 입력받아 만든 루틴은 해당 사용자에게만 제공한다.
- 해결하려는 점: 일반적인 루틴 카탈로그만으로는 개인의 일정, 운동 경력, 목표, 회복 여건, 이용 가능한 환경을 충분히 반영하기 어렵다.
- 정리된 제안: 모바일은 핵심 질문 중심의 빠른 생성·수정 흐름으로, PC는 AI 대화와 필수 입력 폼을 나란히 사용하는 상세 설계 화면으로 구성한다. 생성 결과는 기존 Trainlog 프로그램·루틴 실행 흐름에서 바로 수행할 수 있는 개인 전용 데이터로 저장한다.
- 연결 아이디어: `TL-I-002`, `TL-I-003`, `TL-I-004`
- 남은 질문: 유료 범위와 생성 횟수, 필수 입력 정보, AI와 규칙 기반 검증의 역할, 생성 루틴의 수정·재생성 방식, 모바일과 PC의 기능 차이, 건강·부상 정보의 처리 및 안전 고지.
- 구현 메모: 기존 루틴과 8주 프로그램의 차이를 먼저 정해야 한다. 생성 결과의 버전·근거·사용자 수정 이력을 보존하고, 민감한 사용자 정보와 AI 비용을 고려해야 한다. 구현 전 개인화 운동 처방의 근거와 안전 한계를 조사한다.
- 결과: 미착수

### TL-I-002 — 루틴 공개·공유·탐색

- 상태: `수집`
- 분류: `수익화`, `커뮤니티`
- 기록일: 2026-08-30
- 사용자 메모: 사용자가 만든 루틴을 공유할 수 있게 하고, 공개·비공개 여부를 설정해 다른 사용자들의 루틴을 탐색하는 기능으로 확장한다.
- 해결하려는 점: 개인이 만든 좋은 루틴이 한 계정 안에만 머물며, 다른 사용자는 다양한 실전 루틴을 발견하거나 재사용하기 어렵다.
- 정리된 제안: 루틴마다 공개 범위를 두고, 공개된 루틴은 탐색·상세 보기·내 계정으로 복사할 수 있게 한다. 원본과 복사본을 분리해 원작자의 수정이 이미 복사한 루틴을 예기치 않게 바꾸지 않도록 한다.
- 연결 아이디어: `TL-I-001`
- 남은 질문: 공개 범위 단계, 작성자 표시 방식, 검색·정렬 기준, 좋아요·저장·신고 필요성, AI 생성 루틴 표기, 유료 사용자 전용 범위, 부적절하거나 위험한 루틴의 검수 방식.
- 구현 메모: 공개 데이터용 별도 읽기 정책과 개인정보 제거가 필요하다. 공유 시 운동 카탈로그의 사용자 소유 종목을 다른 사용자가 어떻게 복사할지도 설계한다.
- 결과: 미착수

### TL-I-003 — 헬스장 기구 프로필

- 상태: `수집`
- 분류: `수익화`, `헬스장 연동`
- 기록일: 2026-08-30
- 사용자 메모: 헬스장의 머신을 등록해 사용자가 한 번에 내 종목으로 추가하고, 루틴을 생성할 때 해당 헬스장의 이용 가능한 기구를 고려하게 한다.
- 해결하려는 점: 사용자가 이용할 수 없는 기구가 루틴에 포함될 수 있고, 헬스장을 옮기거나 새로 등록할 때 종목 환경을 일일이 설정해야 한다.
- 정리된 제안: 헬스장별 기구·운동 가능 목록을 프로필로 만들고, 사용자가 다니는 헬스장을 선택하면 자신의 운동 환경에 일괄 반영한다. AI 맞춤 루틴 생성 시 이 환경을 제약 조건으로 사용한다.
- 연결 아이디어: `TL-I-001`, `TL-I-004`
- 남은 질문: 기구 목록의 등록·검수 주체, 헬스장 변경 시 개인 종목 처리, 같은 기구의 브랜드·세팅 차이, 복수 헬스장 지원, 헬스장이 직접 관리하는 유료 기능 여부.
- 구현 메모: 공통 운동 종목, 사용자 소유 종목, 헬스장 기구의 관계를 별도 데이터 모델로 설계해야 한다. 초기에는 대표 헬스장 프로필을 수동 등록하는 작은 범위로 검증할 수 있다.
- 결과: 미착수

### TL-I-004 — 트레이너–회원 연동

- 상태: `수집`
- 분류: `수익화`, `헬스장 연동`, `B2B`
- 기록일: 2026-08-30
- 사용자 메모: PT 트레이너와 회원을 연결하고, 회원 관리나 트레이너에 특화된 메뉴 또는 별도 앱으로 확장한다.
- 해결하려는 점: 트레이너가 회원의 루틴, 수행 기록, 진행 상황을 한 흐름에서 처방하고 확인하기 어렵다.
- 정리된 제안: 회원의 명시적 동의를 바탕으로 트레이너가 루틴을 배정하고 수행 결과를 확인하는 연결 구조를 만든다. 먼저 Trainlog 안의 역할별 메뉴로 검증하고, 사용성이나 사업 범위가 충분히 달라질 때 별도 트레이너 앱을 검토한다.
- 연결 아이디어: `TL-I-001`, `TL-I-003`
- 남은 질문: 트레이너 인증 방식, 회원 초대·연결 해제, 조회·수정 권한, 여러 트레이너 관계, 채팅·피드백 필요성, 결제 주체와 요금제, 개인정보 및 민감 건강정보 동의·보존 정책.
- 구현 메모: 현재 사용자 단독 소유를 전제로 한 RLS와 저장소 계약을 크게 확장하는 기능이다. 처음에는 읽기 전용 진행 현황 공유나 루틴 배정처럼 권한이 좁은 MVP부터 검토한다.
- 결과: 미착수

## 운영 원칙

1. 한 메시지에 여러 생각이 섞여 있으면 독립적으로 구현할 수 있는 단위로 나눈다.
2. 기존 아이디어의 보완이면 새 항목을 만들기보다 해당 항목을 갱신하되, 별도 가치가 있으면 새 ID를 발급하고 서로 연결한다.
3. 모호한 내용도 우선 `수집` 상태로 저장한다. 저장을 미루기 위한 질문은 하지 않는다.
4. 구현을 시작할 때 해당 아이디어를 `구현 중`으로 옮기고, 별도 작업의 범위와 완료 기준으로 사용한다.
5. 구현을 마치면 PR·배포·검증 결과를 기록하고 `완료`로 바꾼다.
6. 운동 프로그램이나 건강 관련 처방처럼 근거 확인이 필요한 아이디어는 구현 전에 출처 조사 항목을 남긴다.
7. 계정 정보, 키, 토큰, 비밀번호 등 비밀값은 사용자 메모에도 기록하지 않는다.
