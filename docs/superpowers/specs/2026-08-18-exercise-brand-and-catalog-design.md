# 종목 브랜드와 종목 관리 화면 설계

작성일: 2026-08-18
상태: 승인 대기

## 배경

같은 "체스트 프레스"라도 기구 제조사가 다르면 같은 60kg가 같은 무게가 아니다. 헬스장을 옮기거나 한 헬스장 안에서 기구를 바꾸면 중량 추이가 기구를 오가며 튄다. 지금은 이걸 구분할 방법이 이름뿐이라, 사용자의 실제 데이터에도 `너틸러스 케이블 체스트 프레스`처럼 브랜드가 이름에 박혀 있다. 이름에 박아 넣으면 브랜드로 묶어 보거나 걸러낼 수 없다.

종목을 다루는 UI도 시트 안의 "새 운동 만들기" 대화상자 하나뿐이다. 한 번 만든 종목을 **고치거나 감출 방법이 없다.** `exercises.is_archived`는 스키마와 도메인 타입에 이미 있는데 값을 바꾸는 코드가 어디에도 없다.

## 결정 사항

사용자와 합의한 세 가지다.

1. **브랜드는 고정 목록에서 고른다.** 자유 입력은 오타로 같은 브랜드가 갈라지고, 갈라지면 묶어 보는 의미가 사라진다.
2. **브랜드가 다르면 별개의 종목이다.** 해머스트렝스 체스트 프레스와 뉴텍 체스트 프레스는 서로 다른 행이고, 1RM·중량 추이도 섞이지 않는다.
3. **관리 화면은 목록·수정·보관까지.** 삭제는 하지 않는다 — 과거 기록이 `exercise_id`로 참조하고 있어 지우면 기록이 깨진다.

## 목표

브랜드를 이름에서 분리해 데이터로 만들고, 만든 종목을 고치고 감출 수 있게 한다.

## 설계

### 1. 데이터 모델

`exercises`에 컬럼 하나를 더한다.

```sql
alter table public.exercises add column brand text;
```

`equipment`가 그렇듯 DB에는 제약을 걸지 않고 앱이 목록을 관리한다. 이 저장소의 기존 방식과 같고, 브랜드 목록은 앞으로 늘어날 값이라 DB 제약으로 굳히면 목록을 늘릴 때마다 마이그레이션이 필요해진다.

```ts
export type ExerciseBrand =
  | 'hammer_strength' | 'nautilus' | 'nutec' | 'cybex' | 'life_fitness'
  | 'technogym' | 'matrix' | 'precor' | 'panatta' | 'watson' | 'star_trac'

// Exercise
brand: ExerciseBrand | null
```

`null`은 "브랜드 없음"이다. 바벨·덤벨·맨몸 운동에는 제조사를 붙일 일이 없으므로 기본값이자 대부분의 값이다.

**목록에 없는 브랜드는 어떻게 하나.** 목록을 고정하기로 한 이상 앱에서 새 브랜드를 만들 수는 없다. 대신 **종목 이름 자체는 자유 입력이라 `왓슨 로우`처럼 이름에 적으면 된다** — 지금 하던 방식 그대로다. 목록에 자주 등장하는 브랜드가 생기면 목록에 추가하는 한 줄 변경으로 처리한다. 이 한계를 관리 화면의 브랜드 선택 옆에 문구로 밝힌다.

**목록 근거.** 사용자의 기존 데이터(`너틸러스`)와 국내 헬스장에 흔한 제조사를 담았다. 순서는 국내 보급률 어림을 따르되, 화면에서는 한글 이름 그대로 보여준다.

### 2. 표시 규칙

브랜드는 **이름 앞의 작은 배지**로 그린다. 이름에 합쳐 한 줄로 만들면 `해머스트렝스 체스트 프레스`가 되어 좁은 화면에서 두 줄로 넘어가고, 무엇이 브랜드고 무엇이 종목인지 눈으로 구분되지 않는다.

```
[해머스트렝스]  체스트 프레스
                가슴 · 머신
```

브랜드가 `null`이면 배지를 그리지 않는다. 빈 자리를 남기지 않는다.

### 3. 스냅샷과 과거 기록

`workout_exercises.exercise_name`과 `routine_exercises.exercise_name`은 **종목을 추가한 시점의 이름을 복사해** 둔다. 기록은 "그때 그 이름으로 한 운동"이므로 이 복사는 유지한다.

브랜드도 같은 규칙을 따른다. **종목을 운동이나 루틴에 넣을 때 `exercise_name`에 브랜드를 합쳐 저장한다** — `해머스트렝스 체스트 프레스`. 두 자식 테이블에 `brand` 컬럼을 더하지 않는 이유는 셋이다.

- 마이그레이션이 테이블 하나로 끝난다.
- 과거 기록·공유 카드·통계는 이름 문자열만 읽어 그리므로 코드를 고칠 곳이 없다.
- 기록의 브랜드는 **바뀌면 안 된다.** 나중에 종목의 브랜드를 고쳐도 이미 한 운동의 기록은 그때 기구 그대로여야 한다. 스냅샷이 이 성질을 공짜로 준다.

대신 화면에 보이는 카탈로그(피커·관리 화면·종목 선택)는 `brand` 필드를 읽어 배지로 그린다. **같은 정보가 두 곳에 다른 모양으로 있는 셈이라 헷갈리기 쉬우니, 합성 함수를 한 곳에 두고 스냅샷을 만드는 모든 경로가 그것만 쓰게 한다.**

```ts
// src/features/workout/exerciseLabels.ts
/** 기록에 복사해 넣을 이름. 카탈로그 표시에는 쓰지 않는다(그쪽은 배지). */
export function snapshotExerciseName(exercise: Pick<Exercise, 'name' | 'brand'>): string
```

호출처는 두 곳이다: `WorkoutRunner`의 종목 추가, `RoutineManager`의 종목 추가.

### 4. 종목 관리 화면 (`/exercises`)

새 라우트를 만들고 `더보기` 메뉴에 넣는다(하단 탭 넷은 그대로 둔다). 종목 추가 시트의 머리에도 "관리" 링크를 둬, 운동 중에 잘못 만든 종목을 바로 고칠 수 있게 한다.

**목록**
- 검색(이름), 부위 필터, 장비 필터, **브랜드 필터**
- 보관된 종목은 기본으로 숨기고, "보관함 보기" 토글로 확인한다
- 각 행: 브랜드 배지 · 이름 · `부위 · 장비` · 기본 휴식

**수정** — 행을 누르면 대화상자가 열린다. 이름, 브랜드, 주요 부위, 장비, 기본 휴식을 고친다. `saveExercise`가 이미 `id`를 받는 upsert라 저장소 계약은 바뀌지 않는다.

**보관** — `isArchived`를 켠다. 보관된 종목은 **종목 추가 시트에서 사라지지만 과거 기록에는 그대로 남는다.** 되돌리기도 같은 자리에서 한다.

**정정(구현 중 확인).** 설계 시점에는 `listExercises()`가 보관 여부를 거르지 않는다고 적었으나 **틀렸다.** 계약에 이미 `listExercises({ includeArchived })`가 있고 두 어댑터 모두 기본값으로 보관 종목을 제외한다. 따라서 화면에서 따로 거를 필요가 없다 — 관리 화면만 `includeArchived: true`로 부르고, 나머지 화면은 지금처럼 옵션 없이 부르면 된다. 다만 캐시 키는 분리해야 한다. 같은 키를 공유하면 보관함까지 담긴 목록이 종목 추가 시트로 흘러간다.

### 5. 종목 만들기 대화상자

브랜드 선택을 더한다. 지금 필드(이름·주요 부위·장비·기본 휴식) 아래에 붙이고, 목록에 없을 때의 안내를 함께 둔다.

## 마이그레이션 안전성

`add column`뿐이라 비파괴적이다. 기존 행은 `brand`가 `null`이 되고, 지금 코드는 그 컬럼을 읽지 않으므로 **DB를 먼저 적용해도 구 프론트엔드가 그대로 동작한다.** 순서는 DB 먼저, 프론트 나중이다.

기존 이름에 박힌 브랜드(`너틸러스 케이블 체스트 프레스`)는 **자동으로 옮기지 않는다.** 이름에서 브랜드를 기계적으로 뽑아내려면 문자열을 추측해야 하고, 틀리면 사용자가 직접 지은 이름을 망가뜨린다. 관리 화면에서 손으로 고치면 되는 양이고, 고치지 않아도 지금과 똑같이 동작한다.

## 비포함

- 브랜드별 통계(브랜드로 묶은 볼륨·추이). 종목 단위 분리로 이미 기록은 갈라지므로, 묶어 보는 화면은 필요해지면 따로 만든다.
- 종목 삭제. 과거 기록이 참조한다.
- 유산소 기록 단위(거리·시간). 별도 TODO이고 `WorkoutSetRecord`를 건드리는 다른 변경이다.

## 검증

```bash
npm run lint && npx tsc -b && npm test && npm run build
```

테스트로 덮을 것:
- 브랜드가 있는 종목을 운동에 추가하면 기록에 합성된 이름이 남는다
- 브랜드가 `null`이면 이름 그대로 남는다
- 보관한 종목이 종목 추가 시트에서 사라지고 관리 화면 보관함에는 남는다
- 종목을 수정해도 이미 기록된 이름은 바뀌지 않는다

Supabase 경로는 mock으로 검증되지 않으므로(이 저장소의 알려진 한계) 배포 후 수동 확인 항목으로 남긴다: 브랜드를 넣어 만든 종목이 새로고침 후에도 브랜드를 유지하는지.
